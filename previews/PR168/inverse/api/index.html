API reference

The entries below document CorleoneInverse-owned APIs and methods of shared functions. Re-exported Corleone and NonlinearSolve APIs retain their own documentation in the Corleone manual. The shared optimization helpers include constraint_jacobian_sparsity and lagrangian_hessian_sparsity for supported shooting problems.

Data and experiments

CorleoneInverse.Experiment — Type
Experiment(t, y; σ = nothing, u0 = nothing, controls = nothing)
Experiment(times, ys; σ = nothing, u0 = nothing, controls = nothing)

The time-series observations of a single experiment of a dynamical system, together with the measurement noise level, the initial conditions used to simulate this experiment and optionally the fixed controls applied in it.

There are two equivalent ways to describe the observations:

  1. Shared-grid matrix form Experiment(t, y): t is the observation time vector and every measured quantity is observed at every time point in t. y is either an AbstractVector of length length(t) (a single measured quantity) or an AbstractMatrix of size (n_obs, length(t)) measuring n_obs quantities at each time point (one row per measured component, matching the ordering the layer's observed map returns).
  2. Per-quantity form Experiment(times, ys): a different set of observation time points per measured quantity. times and ys are vectors-of-vectors with one entry per measured quantity: the k-th quantity of the layer's observed map is observed at time points times[k] with values ys[k] (length(times[k]) == length(ys[k])). This is useful when e.g. different species of the model are sampled at different times, as chosen by an optimal experimental design.

Arguments (matrix form)

  • t: Observation time points as an AbstractVector of reals.

Keywords

  • σ: Measurement uncertainty (noise scale). For the shared-grid matrix form it may be
    • a scalar (shared by all observations),
    • an AbstractVector of length n_obs (per measured component), or
    • an AbstractMatrix of size (n_obs, length(t)) (per observation).
    For the per-quantity form it may be a scalar (shared) or a vector-of-vectors with one noise series per quantity (length(σ[k]) == length(times[k])). When provided, weighted residuals (y_obs - y_model) ./ σ are used in the least-squares problem. When nothing, unweighted residuals are used.
  • u0: Initial conditions used to simulate this experiment. Either nothing (the initial conditions of the differential-equation problem the layer is built from are used) or an AbstractVector of the same length as the state vector of the problem.
  • controls: A tuple of control_index => annotation => switching_times pairs (Tunable(control_index; default, lowerbound, upperbound) => switching_times), specifying the fixed piecewise-constant control functions applied in this experiment. The annotation provides the control values (via default) and bounds, and the switching times are the interior interval boundaries; the first interval starts at the problem's initial time. Control values are not estimated: they are treated as fixed inputs of the experiment design (e.g. produced by optimal experimental design).

Examples

t = collect(0.0:0.5:5.0)
y = [0.1, 0.25, 0.6, 1.1, 1.9, 3.0, 4.5, 6.2, 8.1, 10.2, 12.5]
exp = Experiment(t, y; σ = 0.05, u0 = [1.0])

# An experiment with a fixed control acting on parameter 1
# (five unit values on the intervals (0,1), (1,2), (2,3), (3,4), (4,5))
control = Tunable(1; default = ones(5), lowerbound = 0.0, upperbound = 1.0) =>
    collect(1.0:1.0:4.0)
exp = Experiment(t, y; σ = 0.05, u0 = [1.0], controls = (1 => control,))

# Two quantities observed at different time points (per-quantity form)
exp = Experiment([prey_times, predator_times], [prey_data, predator_data]; σ = 0.05)
CorleoneInverse.ExperimentData — Type
ExperimentData(t, y; σ = nothing, u0 = nothing)
ExperimentData(experiments::Experiment...)
ExperimentData(experiments::AbstractVector{<:Experiment})

Container for the time-series observations of one or more experiments of a dynamical system that are used to fit model parameters.

A single experiment can be constructed directly from its observation times and values. Multiple experiments are constructed from one or more Experiment objects. All experiments are simulated with the same model and share the same (tunable) parameters; each experiment may have its own observation times, measurement noise and initial conditions. The least-squares residuals of all experiments are concatenated into a single residual vector.

Arguments (single-experiment constructor)

  • t: Observation time points as an AbstractVector of reals.
  • y: Observed values, see Experiment.

Keywords (single-experiment constructor)

  • σ: Measurement uncertainty, see Experiment.
  • u0: Initial conditions used to simulate this experiment, see Experiment.

Examples

# A single experiment
t = collect(0.0:0.5:5.0)
y = [0.1, 0.25, 0.6, 1.1, 1.9, 3.0, 4.5, 6.2, 8.1, 10.2, 12.5]
data = ExperimentData(t, y; σ = 0.05)

# Two experiments with different initial conditions, simulated with the same model
data = ExperimentData(
    Experiment(t, y; σ = 0.05, u0 = [1.0]),
    Experiment(t2, y2; σ = 0.05, u0 = [2.0]),
)

# Existing single-experiment `ExperimentData`s can also be combined directly:
data1 = ExperimentData(t, y; σ = 0.05, u0 = [1.0])
data2 = ExperimentData(t2, y2; σ = 0.05, u0 = [2.0])
data = ExperimentData(data1, data2)

Layers and problems

CorleoneInverse.ParameterEstimationLayer — Type
ParameterEstimationLayer{L<:Tuple, O, D} <: LuxCore.AbstractLuxWrapperLayer{:layer}

Wraps one Corleone shooting layer per experiment together with an observation map and the measured data so that the parameters of the underlying differential-equation problem can be fitted with a least-squares approach.

Fields

  • layer: One Corleone shooting layer per experiment (all built from the same problem)

  • observed: Observation map (u, p, t) -> y, returning the measured quantities of a state u at time t

  • data: The measured data

All experiments are simulated with the same model: every wrapped shooting layer is built from the same differential-equation problem, and the tunable model parameters are shared between the experiments. Each experiment is simulated from its own initial conditions (given in the data, or the initial conditions of the problem) and sampled at its own observation times (the shooting layer of experiment i is built with saveat = data.t[i]). All experiments share the problem's time span tspan; an experiment observed over a shorter interval only uses the model trajectory at its own observation times when building the residuals. The least-squares residuals of all experiments are concatenated into a single residual vector.

Like the underlying ShootingLayer, this layer is a callable Lux layer: LuxCore.setup produces the initial parameters and states (shared by all experiments), and calling the layer with (nothing, ps, st) integrates the problem for every experiment. A single-experiment layer returns one Trajectory; a multi-experiment layer returns a tuple with one Trajectory per experiment. The observed quantities at the data time points are obtained by applying the layer's observed map to the trajectory states.

The layer only treats the tunable parameters of the wrapped shooting layers as degrees of freedom. In particular, fixing individual parameters (e.g. via bounds_p with equal lower and upper bounds on the wrapped layer) is respected, so a subset of the model parameters can be kept at known values while the rest are estimated. To estimate only a chosen subset of the model parameters (and keep every other parameter fixed at its value in prob.p), pass the params keyword to the convenience constructors ParameterEstimationLayer(prob, alg, data; params = ...); params is forwarded to the underlying ShootingLayer. Tunable initial conditions (tunable_ic) are shared between all experiments: the tunable entries of the state vector are fitted jointly while the remaining entries stay at each experiment's prescribed initial conditions.

CorleoneInverse.ParameterEstimationProblem — Type
ParameterEstimationProblem <: SciMLBase.AbstractNonlinearProblem

A lightweight container tying a ParameterEstimationLayer to a flat vector of optimization variables (the tunable parameters and initial conditions of the wrapped shooting layer) so that the least-squares residuals can be minimized with any NonlinearSolve solver.

For a plain parameter-estimation setup (no tunable initial conditions, no controls) the optimization variables are exactly the tunable model parameters. Parameters that are fixed on the wrapped layer (e.g. provided via bounds_p with coincident lower/upper bounds) are not part of the optimization variables and are kept at their values.

With a multiple-shooting setup (a ShootingLayer with lifted local states) the flat vector additionally contains the local shooting initial conditions of every experiment (see ParameterEstimationLayer), which keep the trajectory continuous at the shooting points.

Parameter transforms

By default the optimizer works directly on the natural parameters. The transforms keyword instead fits a reparameterized internal variable $\phi$ for every entry of the shared [u0; p] block (local shooting states are never transformed), with the natural value recovered as $\theta = \mathrm{from\_internal}(t, \phi)$ (see AbstractParameterTransform). A transform other than Identity replaces the natural bounds of that variable with an unconstrained internal variable (for Log and Logit the constraint is encoded in the transform's range). The flat vector x0 (and every other flat vector accepted or returned by this problem) is always expressed in the internal space.

transforms accepts nothing (the default, all Identity), a single AbstractParameterTransform applied to every shared entry, or a vector/tuple with exactly one transform per shared entry (useful when tunable initial conditions and model parameters need different transforms).

Parameter regularization

By default the optimizer solves a pure (weighted) least-squares problem. The regularization keyword augments the objective with a data-independent penalty on the fitted model parameters, most commonly to stabilise ill-conditioned or overparameterized fits. Regularization is expressed as extra residuals appended after the observations (and any multiple-shooting continuity residuals), so regularize is honored by every nonlinear least-squares solver (Gauss-Newton, Levenberg-Marquardt, trust-region, ...) and by the Optimization.jl extension without any solver-specific code.

By default only the model parameters p of the shared [u0; p] block are penalized: tuned initial conditions u0 and the local multiple-shooting states are never regularized. The penalty is evaluated on the natural parameter values (so reference and per-parameter weights are in natural units). See AbstractRegularizer, L2Regularizer, L1Regularizer and ElasticNetRegularizer. Any other callable mapping the penalized natural parameter vector to a residual vector can be used directly as a custom regularizer.

Fields

  • layer: The wrapped parameter-estimation layer

  • ps0: Structured initial parameters of the first experiment ((u0, p, controls) for single shooting, or an (interval_1, ...) NamedTuple for multiple shooting)

  • ps0s: Tuple of the layer parameters of every experiment (used to expand the shared optimization variables per experiment for multiple shooting)

  • st: The layer state

  • x0: Flat vector of optimization variables (in the internal, transformed space)

  • lb: Flat lower bounds of the optimization variables (in the internal space, or nothing)

  • ub: Flat upper bounds of the optimization variables (in the internal space, or nothing)

  • transforms: One AbstractParameterTransform per entry of the shared [u0; p] block (local shooting states are always Identity)

  • residual: In-place residual function (res, x, p) -> res reconstructing the structured layer parameters from x

  • residual_oop: Out-of-place residual function (x, p) -> r (reverse-mode-AD compatible), see residual

  • shooting_scale: Multiplier applied to the appended shooting (continuity) residuals so they can be weighted relative to the observation residuals

  • n_residuals: Total number of residuals (observations + multiple-shooting continuity constraints + regularization)

  • n_shooting_constraints: Number of multiple-shooting continuity residuals (the n_shooting_constraints entries after the observation block)

  • n_regularization_residuals: Number of regularization residuals (the trailing block), see AbstractRegularizer

  • reg: The resolved regularizer (θ_pen) -> r_reg, or nothing when no regularization is in effect

Constructors

  • ParameterEstimationProblem(layer; rng, x0, shooting_scale, transforms, regularization)

The low-level NonlinearSolve.NonlinearLeastSquaresProblem can be built directly via problem. Most users construct that problem through the convenience constructor NonlinearSolve.NonlinearLeastSquaresProblem(pe::ParameterEstimationLayer; kwargs...).

CorleoneInverse.model_values — Function
model_values(pe::ParameterEstimationLayer, traj)
model_values(pe::ParameterEstimationLayer, traj, times)

Evaluate the observation map of pe at every time point of the trajectory traj and return the predicted values as a matrix of size (n_obs, n_t). The data time points of pe are expected to be a subset of traj.t (the layer is constructed with saveat = data.t automatically, so this holds by default). The three-argument variant evaluates the observation map at the given times instead of all of traj.t.

If a trajectory only partially covers the requested times (e.g. a shooting sub-interval that diverged mid-solve and did not reach every observation time), the uncovered columns are returned as NaN rather than aborting the calculation, so that a least-squares optimizer sees a non-finite objective and can back off. It is only an error when no requested time is present in the trajectory.

CorleoneInverse.residual — Function
residual(pe, ps, st[, tstops])

Return the vector of least-squares residuals as a new array (the out-of-place counterpart of residuals!). It uses only functional array operations, so – unlike residuals! – it can be differentiated with reverse-mode automatic differentiation. Single shooting works with both Zygote.jl and ReverseDiff.jl; multiple shooting works with ReverseDiff.jl (the root package's multiple-shooting trajectory assembly mutates, so it is not Zygote-differentiable). The residual layout is identical to residuals!: all observation residuals first, then the multiple-shooting continuity residuals. The optional positional argument is forwarded to the layer evaluation; ParameterEstimationProblem passes the precomputed per-experiment segment grids here so they are not re-assembled on every call.

CorleoneInverse.residuals! — Function
residuals!(res, pe::ParameterEstimationLayer, ps, st[, alg])

Compute the least-squares residuals res = (y_obs - y_model) ./ σ (or unweighted when the data has no prescribed noise scale σ) for the parameter values ps and the layer state st, writing them in-place into res. The residuals of each experiment are stacked column-wise over the observed components first, then over the time points, and the residuals of all experiments are concatenated in the order of the experiments. In the per-quantity layout (each quantity measured on its own time grid), the residuals of experiment i are stacked quantity by quantity: the residuals of quantity k over its own time grid, in the order of exp.times.

The optional positional argument is forwarded to the layer evaluation; ParameterEstimationProblem passes the precomputed per-experiment segment grids here so they are not re-assembled on every call.

This is the objective behind the NonlinearLeastSquaresProblem constructed by ParameterEstimationProblem and can be used directly with any NonlinearSolve least-squares solver.

CorleoneInverse.n_shooting_constraints — Function
n_shooting_constraints(pe::ParameterEstimationLayer)

Total number of shooting continuity (matching) residuals over all experiments of pe, computed from each experiment's shooting layer. This is zero when every experiment uses a single-shooting layer (a ShootingLayer without lifted local states).

Note

This convenience method recomputes the layer states from the layer, which is not

type-stable for multiple-shooting layers. Prefer the n_shooting_constraints field of a ParameterEstimationProblem, which is computed once at construction.

Fitting and uncertainty

CorleoneInverse.ParameterEstimate — Type
ParameterEstimate

Point estimate of the fitted parameters together with their asymptotic uncertainties obtained from the (weighted) least-squares covariance.

Fields

  • x: Flat vector of fitted parameter values

  • names: Parameter names (or nothing)

  • covariance: Estimated covariance matrix of the parameters

  • std_errors: Estimated standard errors (sqrt.(diag(covariance)))

  • residual_variance: Estimated residual variance σ̂²

  • rss: Residual sum of squares (RSS) of the (weighted) observation residuals at the optimum (multiple-shooting continuity residuals and regularization penalty residuals are excluded)

  • degrees_of_freedom: Degrees of freedom n - p (observation residuals minus estimated parameters)

  • confidence_level: Confidence level used for confidence_intervals

  • confidence_intervals: Asymptotic confidence intervals as a vector of (lower, upper) tuples

  • n_parameters: Number of fitted parameters p

  • n_observations: Number of observations n

  • r_squared: R² (coefficient of determination) of the weighted observation residuals

  • adjusted_r_squared: Adjusted R² (penalized for the number of fitted parameters)

  • correlation: Parameter correlation matrix derived from covariance

  • condition_number: Condition number of the reduced residual Jacobian (large values indicate near non-identifiability)

The covariance is estimated from the residual Jacobian $J$ at the optimum,

\[\Sigma = \hat{\sigma}^2 \, (J^\top J)^{-1},\]

where $\hat{\sigma}^2 = \mathrm{RSS}/(n - p)$ is the unbiased estimate of the residual variance, $\mathrm{RSS}$ the sum of squared (weighted) observation residuals (multiple-shooting continuity residuals are excluded), $n$ the number of observations and $p$ the number of fitted parameters (including any nuisance local shooting states). When the data specifies measurement noise $\sigma$, the residuals (and hence $J$) are the weighted ones, so that $(J^\top J)^{-1}$ is the weighted least-squares covariance.

When an AbstractRegularizer is in effect, the appended penalty residuals are included in the residual Jacobian, so the covariance is the MAP / posterior covariance $(J_{data}^T J_{data} + Lambda)^{-1} sigma^2$ (with $Lambda = J_{reg}^T J_{reg}$); the standard errors shrink as the regularization strength grows. $RSS$, $sigma^2$ and the degrees of freedom are still computed from the observation residuals alone.

Parameter transforms

CorleoneInverse.AbstractParameterTransform — Type
AbstractParameterTransform

Supertype of the parameter transforms accepted by ParameterEstimationProblem through its transforms keyword. A transform is a smooth bijection between the natural parameter value $\theta$ (used by the model and reported to the user) and the internal value $\phi$ that the optimizer fits:

\[\theta = \mathrm{from\_internal}(t, \phi), \qquad \phi = \mathrm{to\_internal}(t, \theta).\]

Implemented transforms

  • Identity: $\theta = \phi$ (no transform, natural bounds are kept).
  • Affine: $\theta = a \phi + b$ (scaling/centering, exactly linear).
  • Log: $\theta = e^{\phi}$ (strict positivity, $\theta > 0$).
  • Logit: $\theta = lb + (ub - lb)\,\sigma(\phi)$ (box constraint $lb < \theta < ub$).

Any transform other than Identity makes the corresponding internal variable unconstrained (its natural bounds are dropped, since the transform's range encodes the constraint).

CorleoneInverse.Identity — Type
Identity()

The trivial transform $\theta = \phi$. It changes neither the parameterization nor the bounds, and is the default for every optimization variable when no transforms are given.

CorleoneInverse.Affine — Type
Affine(a, b)

Linear (affine) transform $\theta = a\phi + b$ with $a \neq 0$. Because the derivative $d\theta/d\phi = a$ is constant, this is a pure rescaling/centering: it can be used to bring parameters of very different magnitudes onto a common scale (improving the conditioning of the least-squares problem) and it is the only non-trivial transform for which the delta method and the back-transformed confidence interval are exact (the interval stays symmetric).

Example

# Fit a parameter that is naturally O(1e6) on an O(1) scale.
transforms = [Affine(1.0e6, 0.0)]
CorleoneInverse.Log — Type
Log()

Logarithmic transform $\theta = e^{\phi}$ ($\phi = \log \theta$) enforcing strict positivity $\theta > 0$ with an unconstrained internal variable. This is the natural choice for rates, variances, scale parameters and other strictly positive quantities, and it makes the back-transformed confidence interval asymmetric and automatically positive.

CorleoneInverse.Logit — Type
Logit(lb, ub)

Logistic transform mapping the real line onto the open interval $(lb, ub)$:

\[\theta = lb + (ub - lb)\,\sigma(\phi), \qquad \sigma(\phi) = \frac{1}{1 + e^{-\phi}}.\]

It enforces $lb < \theta < ub$ while leaving the internal variable $\phi$ unconstrained, so a box-constrained fit can be solved with an unbounded solver (and hence with any AD backend, avoiding the mutating bounds transformation of bounded solvers).

Example

# Keep a rate in (0, 1) without using a bounded solver.
transforms = [Logit(0.0, 1.0)]

Regularization

CorleoneInverse.AbstractRegularizer — Type
AbstractRegularizer

Supertype of the parameter regularizers accepted by ParameterEstimationProblem through its regularization keyword.

A regularizer augments the least-squares objective with a data-independent penalty on the fitted model parameters (by default the model parameters p, never the tuned initial conditions or the local multiple-shooting states). A regularizer is a callable

(r::AbstractRegularizer)(θ_pen) -> r_reg::AbstractVector

mapping the vector of penalized natural parameter values θ_pen to a vector of additional residual contributions r_reg. Appending these residuals leaves the objective as $\tfrac12\|r_{\mathrm{data}}\|^2 + \tfrac12\|r_{\mathrm{reg}}\|^2$.

Built-in regularizers

  • L2Regularizer: $\lambda \sum_i w_i^2 (\theta_i - \mathrm{ref}_i)^2$ (ridge).
  • L1Regularizer: $\lambda \sum_i w_i |\theta_i - \mathrm{ref}_i|$ (lasso).
  • ElasticNetRegularizer: combination of L2 and L1.

Any callable matching the signature above can be used directly (e.g. a closure or a struct returning custom residual contributions), so new regularization terms can be added without changing the package.

CorleoneInverse.L2Regularizer — Type
L2Regularizer(λ; reference = nothing, weights = nothing)

Ridge ($L_2$) regularization penalizing the squared deviation of the penalized model parameters from a reference value,

\[\tfrac12\|r_{\mathrm{reg}}\|^2 = \lambda \sum_i w_i^2 \,(\theta_i - \mathrm{ref}_i)^2 .\]

The penalty residuals are $\sqrt{\lambda}\,w_i\,(\theta_i - \mathrm{ref}_i)$, so the strength λ is measured relative to the (measurement-noise-weighted) observation residuals: $\lambda = 1$ adds residual rows comparable to a single $O(1)$ observation residual.

Arguments

  • λ: Regularization strength (must be > 0).

Keywords

  • reference: Vector of shrinkage targets (or nothing for zeros), one per penalized parameter, in natural units.
  • weights: Per-parameter scaling (or nothing for ones), one per penalized parameter.

reference/weights may also be supplied through the regularization_reference / regularization_weights keywords of ParameterEstimationProblem, which take precedence.

CorleoneInverse.L1Regularizer — Type
L1Regularizer(λ; reference = nothing, weights = nothing)

Lasso ($L_1$) regularization penalizing the absolute deviation of the penalized model parameters from a reference value,

\[\tfrac12\|r_{\mathrm{reg}}\|^2 = \lambda \sum_i w_i \,|\theta_i - \mathrm{ref}_i| .\]

The penalty residuals are $\sqrt{\lambda}\,\sqrt{w_i\,|\theta_i - \mathrm{ref}_i|}$ kept as separate rows per parameter (see n_regularization_residuals); equivalently the penalty contributes $\lambda \sum_i w_i |\theta_i - \mathrm{ref}_i|$ to $\tfrac12\|r\|^2$. This is non-smooth at $\theta_i = \mathrm{ref}_i$: Gauss-Newton-type solvers treat it through its (biased at the kink) derivative, which is generally fine for pulling parameters toward the reference but does not reliably produce exact zeros. For smooth, well-conditioned shrinkage prefer L2Regularizer or ElasticNetRegularizer.

Arguments

  • λ: Regularization strength (must be > 0).

Keywords

  • reference: Vector of shrinkage targets (or nothing for zeros), one per penalized parameter, in natural units.

CorleoneInverse.profile_likelihood — Function
profile_likelihood(problem, sol; α = 0.05, names = nothing, solver = GaussNewton(),
                   n_points = 41, span = 6.0, expand = true, kwargs...)

Compute profile-likelihood confidence intervals for every fitted parameter of a solved ParameterEstimationProblem.

For each fitted parameter the model is re-fit (with NonlinearSolve) holding that parameter fixed at n_points values sweeping a range around its optimum, while the remaining parameters (and, for multiple shooting, the local shooting states) are re-optimized. The resulting profile of minimized (weighted) residual sum of squares is compared against the likelihood-ratio threshold (see ProfileCurve); the crossings give the (1-α)-level confidence interval. A profile that never rises above the threshold (a flat valley) yields an unbounded interval, flagging that parameter as non-identifiable.

Keywords

  • α: Significance level (default 0.05 → 95% intervals).
  • names: Optional vector of Symbols naming the fitted parameters.
  • solver: Least-squares solver used for the repeated re-fits (default GaussNewton(); use a bounded solver such as BoundedLevenbergMarquardt when the parameters have active bounds).
  • n_points: Number of grid points per parameter (default 41).
  • span: Half width of the sweep as a multiple of the asymptotic standard error (default 6.0). A per-parameter AbstractVector is also accepted.
  • expand: Whether to widen the sweep if a crossing is not initially bracketed (default true), so off-centered profiles still yield finite intervals.
  • kwargs...: Forwarded to the solve calls (tolerances, etc.).

Returns

A ProfileLikelihoodEstimate. Use confidence_interval for the profile intervals and profiles for the per-parameter curves.

profile_likelihood(pe::ParameterEstimationLayer, sol; transforms = nothing,
                   regularization = nothing, shooting_scale = 1.0, kwargs...)

Convenience variant that constructs the ParameterEstimationProblem from the layer pe (with default options) and calls profile_likelihood. The transforms keyword attaches AbstractParameterTransforms to the shared [u0; p] block and must match the transforms the solution was computed with; when the problem is built explicitly it already carries them. The regularization (with regularization_reference / regularization_weights) and shooting_scale keywords are forwarded to the problem construction and must likewise match the options the solution was computed with.
