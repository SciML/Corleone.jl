API Reference

Shooting layers

ShootingLayer returns (trajectory, state). Parameter switches and scheduled initial conditions split the solve into segments. Only active, non-fixed initial conditions contribute matching residuals. See Parallel shooting for independent block execution and Automatic differentiation backends for tested gradient configurations. Segment boundaries are cached in st.timestops during setup and retained in the returned state. After changing a schedule, refresh the cache with st = merge(st, (; timestops = Corleone.get_timestops(layer, nothing, st))).

Corleone.ShootingLayer — Type
struct ShootingLayer{__T_name, __T_problem, __T_alg, __T_ensemblealg, __T_initialcondition, __T_parameter, __T_sys} <: LuxCore.AbstractLuxContainerLayer{(:initialcondition, :parameter)}

A Lux layer that solves a differential equation in segments separated by parameter switches and initial-condition resets. Calling with (input, ps, st) returns (trajectory, next_st), with reset residuals stored in trajectory.residuals. A differential equation problem can be supplied as input; other inputs use the stored problem. A (problem, tstops) tuple supplies an explicit segment grid.

Segment boundaries are computed once during setup and stored in st.timestops. Forward calls reuse that vector and preserve it in the returned state. After changing a schedule, explicitly refresh the cached grid before solving; see get_timestops. For a replacement problem with a different time span, supply its matching grid through the (problem, tstops) call.

EnsembleSerial() solves sequentially. For ODE problems, EnsembleThreads() and EnsembleDistributed() solve independent blocks starting at interior full-state resets. Partial resets remain sequential within a block. Reverse-mode rules record block solves serially; ordinary forward execution uses the ensemble map.

Fields

  • name: The optional name of the shooting layer.

  • problem: The differential equation problem used when no replacement problem is supplied.

  • alg: The differential equation solver algorithm for each segment.

  • ensemblealg: The ensemble algorithm selecting serial, threaded, or distributed block execution.

  • initialcondition: Per-variable initial-condition layers and their reset schedules.

  • parameter: Per-parameter layers supplying parameter values for each segment.

  • sys: The ControlSymbolCache shared with trajectories for symbolic bookkeeping.

Construct a shooting layer from a problem, solver, and annotation => timegrid definitions. Variable annotations define initial-condition resets; remaining definitions configure parameters. fixed_parameters selects parameters held in Lux state.

controls and quadratures select parameter and state subsets by symbol or original index. bounds maps symbols to bound pairs used as annotation defaults. Omitted metadata inherits from the problem cache; explicit annotation bounds take precedence. Metadata does not alter numerical state or parameter layouts.

Corleone.InitialConditions — Type
struct InitialConditions{__T_name, __T_repack, __T_initialconditions} <: LuxCore.AbstractLuxContainerLayer{(:initialconditions,)}

A collection of single-variable InitialCondition layers, analogous to Parameter. Definitions are annotation => timegrid pairs; plain indices and symbols are also accepted as tunable annotations. Variables with no grid pass through their incoming values. Constant annotations store scheduled values in Lux state via FixedLayer.

Calling with (incoming_state, t) returns ((state, residuals), next_st). Residuals are assigned values minus the corresponding incoming values, in state index order. Only active, non-fixed layers contribute residuals. The Boolean vector st.active is allocated during setup and reused on each call. Updating this scheduling metadata is non-differentiable; residual arithmetic is not.

Fields

  • name: The optional name of the initial-condition collection.

  • repack: Reconstructs the problem state from its canonical tunable values.

  • initialconditions: A NamedTuple of per-variable reset or pass-through layers in state index order.

Corleone.InitialConditions — Method
InitialConditions(problem, definitions; name, sys)

Construct per-variable initial conditions from annotation => timegrid definitions. Annotations of kind Val(:variable) select state entries. Unspecified variables pass through their incoming values; Constant definitions store reset values in Lux state. sys supplies symbols, defaults, and annotation bounds.

Corleone.Parameter — Type
struct Parameter{__T_name, __T_repack, __T_parameters} <: LuxCore.AbstractLuxContainerLayer{(:parameters,)}

A collection of per-parameter piecewise-constant layers. Calling with (t, ps, st) returns the reconstructed problem parameters and updated Lux state. Fixed values are held in Lux state through FixedLayer.

Fields

  • name: The optional name of the parameter collection.

  • repack: Reconstructs the problem parameters from their canonical tunable values.

  • parameters: A NamedTuple of per-parameter layers in canonical parameter index order.

Construct parameter layers from annotation => timegrid definitions. Unspecified parameters receive one tunable value initialized from the problem. Constant annotations and entries selected by fixed store values in Lux state. sys supplies symbols, defaults, and annotation bounds.

Corleone.Tunable — Function
Tunable(
;
    index,
    sym,
    kind,
    default,
    lowerbound,
    upperbound,
    integer
)

Construct an annotation whose values are stored in Lux parameters. Supply an index or symbol, a positional selector => default pair, or the index/sym keywords. Optional keywords are kind, default, lowerbound, upperbound, and integer. Missing metadata is resolved from the symbolic container.

Use kind = Val(:variable) for initial-condition resets and Val(:parameter) for parameter definitions. Pair the annotation with its time grid to define a layer.

default accepts a scalar, a vector, or a callback (rng, n::Int) -> values or (rng, times::AbstractVector) -> values. Untyped callbacks retain the count-based interpretation; the count signature wins if both are applicable. State defaults have one value per reset time, in supplied grid order. Parameter defaults have one value per interval; time-based callbacks receive [tspan[1]; switching_times]. A parameter without switching times has one value at tspan[1].

Scalar and vector bounds are checked when resolving annotations. Callback output length and bounds are checked during Lux setup. Vectors and callback results are retained by reference; use a callback that allocates when independent setup arrays are needed.

Trajectories

Saved states and times are available as trajectory.u and trajectory.t, and initial-condition matching residuals as trajectory.residuals. Continuous segment handoffs are stored once; reset boundaries retain both sides, with trajectory.reset_indices pointing to the outgoing states.

The trajectory retains the supplied layer, parameters, and Lux state by reference. Parameter queries evaluate layer.parameter using those objects. In-place changes to them affect subsequent parameter queries. Use SymbolicIndexingInterface.parameter_values_at_time(trajectory, trajectory, t) for values at a time, or getp(trajectory, symbol)(trajectory) for a parameter's history on its parameter-change grid.

Corleone.Trajectory — Type
struct Trajectory{__T_sys, __T_u, __T_t, __T_residuals, __T_reset_indices, __T_layer, __T_ps, __T_st}

Assemble saved segment solutions into a trajectory. Continuous handoffs occur once; initial-condition boundaries retain both the incoming endpoint and outgoing start, even when their states are equal. reset_indices indexes the outgoing samples.

Fields u and t contain the state samples and their times. residuals retains one initial-condition residual vector per segment start. The trajectory stores layer and its supplied Lux parameters ps and state st; parameter histories are evaluated on demand through layer.parameter, rather than stored separately. State samples are shared with the input solutions. Mutating ps or st changes subsequent parameter queries. Gradients through state values, residuals, and parameter values are supported on a fixed time grid; layout and symbolic metadata are not differentiated. The symbolic cache is shared with layer.sys and exposed through SymbolicIndexingInterface.symbolic_container. Query controls, quadrature states, and bounds on that ControlSymbolCache wrapper. No interpolation or integration is performed.

Fields

  • sys: The symbolic bookkeeping cache shared with the shooting layer.

  • u: Saved state samples, sharing their numerical arrays with the segment solutions.

  • t: The actual saved solution times, including both sides of reset boundaries.

  • residuals: Initial-condition residual vectors, one per segment start.

  • reset_indices: Indices in u and t of outgoing samples at initial-condition reset boundaries.

  • layer: The shooting layer used to evaluate parameter values on demand.

  • ps: The supplied Lux parameters, retained by reference for parameter queries and AD.

  • st: The supplied Lux state, retained by reference for parameter queries and AD.

Corleone.Trajectory — Method
Trajectory(layer, ps, st, solutions, residuals)

Assemble saved segment solutions and residuals into a Trajectory. Remove duplicate samples at continuous handoffs while retaining both sides of initial-condition resets. Saved state arrays, parameters, and Lux state are shared.

Symbolic bookkeeping

Retrieve the wrapper with SymbolicIndexingInterface.symbolic_container(trajectory) or SymbolicIndexingInterface.symbolic_container(layer). Control and quadrature queries are defined only on ControlSymbolCache; original state and parameter indices are preserved. See Symbolic bookkeeping.

Corleone.ControlSymbolCache — Type
struct ControlSymbolCache{__T_sys, __T_controls, __T_quadratures, __T_bounds}

Wrap a SymbolicIndexingInterface symbolic container with bookkeeping metadata. controls selects parameters; quadratures selects states that integrate running costs. Selections accept symbols or original indices. All symbols retain their original kind, index and ordering. Controls remain parameters.

bounds maps state or parameter symbols to (lower, upper) pairs. The parent container and supplied bounds dictionary are retained by reference, just as the parent's defaults are. Index-provider queries delegate through symbolic_container. A differential equation problem can also be supplied in place of sys.

Fields

  • sys: The original symbolic index provider, retained by reference.

  • controls: The subset of parameter symbols designated as controls.

  • quadratures: The subset of state symbols designated as running-cost integrals.

  • bounds: State and parameter symbols mapped to (lower, upper) bounds, retained by reference.

Corleone.ControlSymbolCache — Method
ControlSymbolCache(sys; controls, quadratures, bounds)

Construct a bookkeeping wrapper from a symbolic index provider. controls and quadratures accept symbols or original indices; bounds must be keyed by symbols. The parent and bounds dictionary are retained by reference. Passing an existing cache without overrides returns that same cache.

Internal layers and scheduling

These layers compose the public shooting layer. Their grids and activity masks live in Lux state and can be reused between evaluations.

  • name: The optional name of the state variable.
Corleone.InitialCondition — Type
struct InitialCondition{__T_name, __T_lookup, __T_parameter} <: LuxCore.AbstractLuxContainerLayer{(:lookup, :parameter)}

Values for a single state variable at the specified times. There is one value per entry in timegrid, initialized from a scalar, vector, or callback accepting (rng, n::Int) or (rng, times::AbstractVector). Count callbacks take precedence; time-based callbacks receive the grid in its supplied order. Calling the layer with (incoming_value, t) returns the value at the matching grid index, or incoming_value when no time matches. A nothing grid is pass-through and allocates no trainable values.

Fields

  • name: The optional name of the state variable.

  • lookup: Exact-time lookup mapping each scheduled reset time to its value index.

  • parameter: The collection of values assigned at the scheduled reset times.

Corleone.InitialCondition — Method
InitialCondition(timegrid, default; name, cache, bounds)

Construct reset values for one state variable on timegrid. default is a scalar, vector, or count/timepoint initializer as described by Tunable. Times must be unique; nothing selects an empty reset grid. cache is an optional lookup cache. Output length and bounds are checked during Lux setup.

Corleone.FixedLayer — Type
struct FixedLayer{__T_layer} <: LuxCore.AbstractLuxWrapperLayer{:layer}

A wrapper that stores the inner layer's parameters and state in Lux state. The wrapper has no trainable parameters. Calling it forwards its stored values to the inner layer and retains that layer's updated state.

  • layer: The inner layer whose parameters are held fixed in Lux state.

Corleone.lookup! — Function
lookup!(cache, collection, key)

Look up the interval or entry for key, optionally caching the result.

  • cache is a cache for storing already looked up keys. In case of nothing the caching is skipped.
  • collection either an AbstractVector or AbstractDict used for the lookup
  • key the key.

If used with an AbstractVector and Number, lookup defaults to piecewise constant interpolation using searchsortedfirst(collection, key; lt = <=): a switching time belongs to the following interval. Dictionary lookup requires an exact key and returns typemax of its value type when absent. A nothing collection returns index 1.

Corleone.get_timestops — Function
get_timestops(layer, ps, st)
get_timestops(layer, ps, st, T)

Return sorted, unique segment boundaries from the problem time span and the initial-condition and parameter schedules in Lux state. Layer boundaries outside the problem time span are excluded. The result has element type T. Schedules are read exclusively from Lux state, so ps may be nothing. To refresh a layer's cached grid after changing schedules, use merge(st, (; timestops = get_timestops(layer, nothing, st))). Forward evaluation uses st.timestops directly rather than invoking this function.

Corleone.update_active_ics! — Function
update_active_ics!(active, initial_conditions, new_st)

Update the preallocated residual activity mask from per-variable layers and their new Lux states. Only active, non-fixed initial conditions contribute residuals. This scheduling update is non-differentiable; an all-PassThrough tuple clears the mask without checking individual layers.

Corleone.terminal_state — Function
terminal_state(sol)

Return the final state from a time-series solution, a sequence of saved states, or a matrix whose columns are saved states. Supports solver and AD return formats.

Corleone.AbstractAnnotation — Type
abstract type AbstractAnnotation

Metadata for a state or parameter definition, including its selector, default, bounds, kind, and integrality. Concrete annotations are resolved against a symbolic index provider before numerical layers are constructed.

Deprecated constructor functions

These functions return native definitions and layers. See Deprecated constructors for the translation rules and unsupported legacy options.

Corleone.ControlParameter — Function
ControlParameter(t; name, controls, bounds)

Deprecated constructor for a piecewise-constant control. Return a Tunable(name; kind = Val(:parameter), ...) => switching_times definition. Legacy t contains the start of each control interval, so the first entry is removed from the returned switching grid. controls may be a vector, scalar, or legacy callback (rng, times, bounds) -> values. Callbacks run during Lux setup.

Scalar bounds and uniform bound vectors are supported. Nonuniform per-time bounds cannot be represented by the current annotation bounds and are rejected. Pass the returned definition directly to ShootingLayer, or use index => definition in a deprecated shooting constructor to select a parameter independently of name.

Corleone.SingleShootingLayer — Function
SingleShootingLayer(prob, alg; kwargs...)

Deprecated single-shooting constructor returning a ShootingLayer. Translate controls = [index => ControlParameter(...), ...], tunable_ic, bounds_ic, bounds_p, and quadrature_indices into native annotations and symbolic bookkeeping. Initial conditions in tunable_ic are tunable at the problem start; other initial conditions pass through problem.u0. Non-control parameters remain tunable. Extra keywords remake the differential equation problem.

The return value uses the new Lux parameter/state layout, with residuals in trajectory.residuals. Legacy whole-vector initialization callbacks are not supported; set annotation defaults using count or timepoint callbacks instead.

Corleone.MultipleShootingLayer — Function
MultipleShootingLayer(
    prob,
    alg,
    times;
    ensemble_alg,
    initialization,
    kwargs...
)

Deprecated multiple-shooting constructor returning a ShootingLayer. Accept a problem and algorithm, or an existing ShootingLayer, followed by shooting points as a vector or positional arguments. Every state, including quadratures, is lifted at interior shooting points. ensemble_alg selects block execution.

The returned layer uses the native per-variable parameter layout and initial-state matching residuals. Parameters and controls remain shared across shooting blocks. Legacy stage-parameter/control lifting and whole-layer initialization callbacks are not restored; express initial guesses through annotation defaults instead.
