API reference

For workflows, use the Manual. This page includes docstrings for exported APIs and supporting layer types.

Shooting layers

Corleone.ShootingLayer — Type
struct ShootingLayer{__T_name, __T_problem, __T_alg, __T_ensemblealg, __T_initialcondition, __T_parameter, __T_sys} <: LuxCore.AbstractLuxContainerLayer{(:initialcondition, :parameter)}

A Lux layer that solves a differential equation in segments separated by parameter switches and initial-condition resets. Calling with (input, ps, st) returns (trajectory, next_st), with reset residuals stored in trajectory.residuals. A tunable assignment at the global problem start is a free initial value and produces no matching residual. Active tunable interior assignments produce matching residuals; fixed resets do not. Assignments at the final time create no outgoing segment. A differential equation problem can be supplied as input; other inputs use the stored problem. A (problem, tstops) tuple supplies an explicit segment grid.

Segment boundaries are computed once during setup and stored in st.timestops. Forward calls reuse that vector and preserve it in the returned state. After changing a schedule, explicitly refresh the cached grid before solving; see get_timestops. For a replacement problem with a different time span, supply its matching grid through the (problem, tstops) call.

EnsembleSerial() solves sequentially. For ODE problems, EnsembleThreads() and EnsembleDistributed() solve independent blocks starting at interior full-state resets. Partial resets remain sequential within a block. Reverse-mode rules record block solves serially; ordinary forward execution uses the ensemble map.

Fields

  • name: The optional name of the shooting layer.

  • problem: The differential equation problem used when no replacement problem is supplied.

  • alg: The differential equation solver algorithm for each segment.

  • ensemblealg: The ensemble algorithm selecting serial, threaded, or distributed block execution.

  • initialcondition: Per-variable initial-condition layers and their reset schedules.

  • parameter: Per-parameter layers supplying parameter values for each segment.

  • sys: The ControlSymbolCache shared with trajectories for symbolic bookkeeping.

Corleone.ShootingLayer — Method
ShootingLayer(
    problem,
    alg,
    definitions;
    name,
    fixed_parameters,
    ensemblealg,
    controls,
    quadratures,
    bounds
)

Construct a shooting layer from a problem, solver, and annotation => timegrid definitions. Variable annotations define initial-condition resets; remaining definitions configure parameters. fixed_parameters selects parameters held in Lux state.

controls and quadratures select parameter and state subsets by symbol or original index. bounds maps symbols to bound pairs used as annotation defaults. Omitted metadata inherits from the problem cache; explicit annotation bounds take precedence. Metadata does not alter numerical state or parameter layouts.

Corleone.InitialConditions — Type
struct InitialConditions{__T_name, __T_repack, __T_initialconditions, __T_indices} <: LuxCore.AbstractLuxContainerLayer{(:initialconditions,)}

A collection of shared-grid InitialCondition layers, analogous to Parameter. Definitions are annotation => timegrid pairs; plain indices and symbols are also accepted as tunable annotations. Variables with no grid pass through their incoming values. Constant annotations store scheduled values in Lux state via FixedLayer.

Calling with (incoming_state, t) returns ((state, residuals), next_st). Residuals are assigned values minus the corresponding incoming values, in state index order. Only active, non-fixed layers contribute residuals. Set matching = false to apply assignments without producing matching residuals, as used for free initial values at the global problem start. The Boolean vector st.active is allocated during setup and reused on each call. Updating this scheduling metadata is non-differentiable; residual arithmetic is not.

Fields

  • name: The optional name of the initial-condition collection.

  • repack: Reconstructs the problem state from its canonical tunable values.

  • initialconditions: Shared-grid reset layers and pass-through layers, keyed by their first variable symbol.

  • indices: Original state indices represented by each reset or pass-through layer.

Corleone.InitialConditions — Method

Construct per-variable initial conditions from annotation => timegrid definitions. Annotations of kind Val(:variable) select state entries. Unspecified variables pass through their incoming values; Constant definitions store reset values in Lux state. sys supplies symbols, defaults, and annotation bounds.

Corleone.Parameter — Type

A collection of per-parameter piecewise-constant layers. Calling with (t, ps, st) returns the reconstructed problem parameters and updated Lux state. Fixed values are held in Lux state through FixedLayer.

Fields

Corleone.Tunable — Function
Tunable(
;
    index,
    sym,
    kind,
    default,
    lowerbound,
    upperbound,
    integer,
    transform,
    prior
)

Construct an annotation whose values are stored in Lux parameters. Supply an index or symbol, a vector of indices or symbols, a positional selector => default pair, or the index/sym keywords. Optional keywords are kind, default, lowerbound, upperbound, integer, transform, and prior. Missing metadata is resolved from the symbolic container. For an EvaluationLayer keyword, supply a scalar default and let the keyword provide the name.

transform is an increasing scalar transform from internal to natural values (load TransformVariables, e.g. asℝ₊). Lux parameters then store internal values, while defaults and layer outputs remain natural. With no explicit transform, a BoundedTransform stores the bounds and uses identity coordinates. Explicit transforms replace this object and supply their own optimizer bounds; TransformVariables transforms use (-Inf, Inf). prior is a univariate distribution on natural values (load Distributions); see log_prior.

Use kind = Val(:variable) for initial-condition resets and Val(:parameter) for parameter definitions. Pair the annotation with its time grid to define a layer.

default accepts a scalar, a vector, or a callback (rng, n::Int) -> values or (rng, times::AbstractVector) -> values. Untyped callbacks retain the count-based interpretation; the count signature wins if both are applicable. State defaults have one value per reset time, in supplied grid order. Parameter defaults have one value per interval; time-based callbacks receive [tspan[1]; switching_times]. A parameter without switching times has one value at tspan[1].

For vector selectors, supply one default per selector: a vector of scalars gives constant guesses, and a vector of vectors gives per-variable time series. Omitted defaults inherit metadata separately. Bounds, transforms, and priors may be shared or per-selector vectors. Grouped annotations expand into scalar definitions before layer construction.

Scalar and vector bounds are checked when resolving annotations. Callback output length and bounds are checked during Lux setup. Vectors and callback results are retained by reference; use a callback that allocates when independent setup arrays are needed.

Corleone.Annotations — Function
Annotations(sys; kwargs...)

Read state and parameter metadata from a symbolic system. The ModelingToolkit extension returns (; variables, parameters), containing Tunable or Constant annotations with explicit indices, defaults, bounds and kinds. Load ModelingToolkit to use this constructor.

Annotations accept a transform (load TransformVariables) and a univariate prior (load Distributions). Corleone.BoundedTransform — Type
BoundedTransform(lowerbound = -Inf, upperbound = Inf)

Identity mapping with explicit optimization bounds. Forward and inverse mappings preserve values, and the log-Jacobian is zero. In unresolved annotations, nothing bounds inherit symbolic metadata. Explicit transforms replace this default object and supply their own optimization bounds.

Corleone.log_prior — Function

Return the log prior density of the tunable parameters ps of layer with Lux state st. Each value of a collection with a prior contributes logpdf(prior, θ) at its natural value θ, plus the log-Jacobian of its transform, so the density refers to the stored internal values. Values that add_parameter_segments! duplicated for multiple shooting are skipped, so each prior counts once per original value. Collections without a prior contribute nothing.

Fixed collections are skipped.

See Initializing shooting variables for scalar, vector, and count/timepoint callback defaults and helpers for existing parameter buffers.

Corleone.forward_initialization — Function
forward_initialization(rng, layer, ps, st; variables)

Omit ps and st to run LuxCore.setup(rng, layer) and return initialized (ps, st).

Initialize selected interior shooting values by a sequential solve using the current parameter schedule. Preserve assignments at the global start, fixed resets, and unselected tunable resets. At each selected reset, use the incoming solution value, including resets at the final time. Selected matching residuals then vanish up to solver accuracy.

Pass existing ps and st. variables selects original state indices. Work on private copies while solving, then validate bounds and update the existing ps buffers. Return ps; the supplied state and fixed values remain unchanged. This helper currently supports ODE problems and uses the layer's solver serially, regardless of its ensemble algorithm.

Multi-stage transitions and linkages

Chain multiple shooting stages with Stages and connect consecutive stages with StageTransition (substitution) or StageLinkage (a free interface state coupled by a residual constraint). Each layer is stored under the key stage_i following the layer order. See the multi-stage guide and the two-stage reactor tutorial.

Corleone.StageTransition — Type
struct StageTransition{F, P, B} <: LuxCore.AbstractLuxLayer

A lightweight Lux layer that connects consecutive optimal-control stages inside a Stages container. It receives the Trajectory produced by the preceding ShootingLayer and returns the initial state vector of the subsequent stage. The mapping is encoded in the callable f, i.e.

StageTransition((traj, p) -> vcat(last(traj.u)[1:2], 0.0); p = [0.5], bounds = ([0.0], [1.0]))

The transition may carry its own parameters (for example a jump size or a switching cost). They are optimized together with the parameters of the shooting layers and are bounded by bounds. The callable f receives the preceding stage's Trajectory and the transition parameters p, and returns the initial state of the next stage.

Fields

  • f: Function mapping the preceding stage's Trajectory and the parameters to the next stage's initial state

  • p: Initial values of the transition parameters

  • bounds: Lower and upper bounds (lb, ub) of the transition parameters

Corleone.StageLinkage — Type
struct StageLinkage{F, U, BU, T, BT, B} <: LuxCore.AbstractLuxLayer

A Lux layer that links consecutive optimal-control stages by an interface state that is itself a free optimization variable. In contrast to StageTransition, the phase that follows a StageLinkage is not started at the value computed from the preceding phase. Instead the linkage owns the next phase's initial state u0 and imposes a residual

\[\Delta x_{\min} \le u_0 - m\big(x_f^{\mathrm{prev}}, \theta\big) \le \Delta x_{\max}\]

so that the two phases are coupled through a constraint rather than by substitution.

The map m may be

  • the identity (default, StageLinkage(u0)),
  • an affine map m(x, \theta) = A x + B \theta + c (StageLinkage(A, B, c)), or
  • an arbitrary callable m(x, \theta) returning the next initial state (StageLinkage(m; u0 = ...)).

The linkage carries its own tunable parameters: the interface state u0 (bounded by bounds_u0) and, optionally, the jump parameters \theta (bounded by bounds_θ). The residual bounds default to (zeros, zeros), i.e. an exact linkage.

Fields

  • f: Map (x_previous_final, θ) -> x_next_initial used in the linkage residual

  • u0: Initial values of the free interface state (the next phase's initial state)

  • bounds_u0: Lower and upper bounds (lb, ub) of the interface state

  • θ: Initial values of the linkage/jump parameters

  • bounds_θ: Lower and upper bounds (lb, ub) of the linkage/jump parameters

  • bounds: Lower and upper bounds (lb, ub) of the linkage residual u0 - m(x_f, θ)

Corleone.StageLinkage — Method
StageLinkage(u0; kwargs...)

Create an identity linkage: the next phase starts at the free interface state u0, which is coupled to the previous phase's final state by u0 - x_f = 0.

Corleone.StageLinkage — Method
StageLinkage(A, B, c; u0 = c, kwargs...)

Create an affine linkage m(x, θ) = A * x + B * θ + c. This covers projections onto the next phase's state (dimension changes across stages) as well as linear, tunable jumps.

Corleone.linkage_residual — Function
linkage_residual(linkage, ps, prev_traj)

Residual u0 - m(x_f, θ) of a StageLinkage, where x_f is the final state of the preceding phase's trajectory.

Corleone.get_number_of_linkage_constraints — Function
get_number_of_linkage_constraints(stages)

Return the total number of linkage constraints contributed by stages (one per component of every StageLinkage's interface state).

Corleone.linkage_constraint_bounds — Function
linkage_constraint_bounds(stages)

Corleone.Stages — Type
struct Stages{T}

A sequence of optimal-control stages with optional StageTransition and StageLinkage connectors. Stages composes multiple ShootingLayers without pulling Lux.Chain into the optimization problem: it mirrors the chain's per-stage parameter/state bookkeeping, forwards inputs through the stages in application order, and dispatches CorleoneDynamicOptProblem construction.

Build one by listing the stages in application order, e.g.

Stages(stage1, StageTransition((traj, p) -> last(traj.u)), stage2)

Parameters and states are initialized with LuxCore.setup into trees keyed stage_1, stage_2, ... following the layer order. Calling the container stages(nothing, ps, st) runs the whole sequence once and returns the final output with the final state, like a chain would.

Fields

  • layers: The stages and connectors in application order

Trajectories

Corleone.Trajectory — Type
struct Trajectory{__T_sys, __T_u, __T_t, __T_residuals, __T_reset_indices, __T_layer, __T_ps, __T_st}

Assemble saved segment solutions into a trajectory. Continuous handoffs occur once; initial-condition boundaries retain both the incoming endpoint and outgoing start, even when their states are equal. reset_indices indexes the outgoing samples.

Fields u and t contain the state samples and their times. residuals retains one initial-condition residual vector per segment start. The trajectory stores layer and its supplied Lux parameters ps and state st; parameter histories are evaluated on demand through layer.parameter, rather than stored separately. State samples are shared with the input solutions. Mutating ps or st changes subsequent parameter queries without recomputing the saved states. Run the layer again after changing parameters when both histories must describe the same prediction. Gradients through state values, residuals, and parameter values are supported on a fixed time grid; layout and symbolic metadata are not differentiated. The symbolic cache is shared with layer.sys and exposed through SymbolicIndexingInterface.symbolic_container. Query controls, quadrature states, and bounds on that ControlSymbolCache wrapper. No interpolation or integration is performed.

Fields

  • sys: The symbolic bookkeeping cache shared with the shooting layer.

  • u: Saved state samples, sharing their numerical arrays with the segment solutions.

  • t: The actual saved solution times, including both sides of reset boundaries.

  • residuals: State matching residual vectors per segment start; excludes on-demand parameter equalities.

  • reset_indices: Indices in u and t of outgoing samples at initial-condition reset boundaries.

  • layer: The shooting layer used to evaluate parameter values on demand (stored as a Ref; traj.layer returns the layer).

  • ps: The supplied Lux parameters, retained by reference for parameter queries and AD.

  • st: The Lux state used for parameter queries (stored as a Ref; traj.st returns the state).

Corleone.Trajectory — Method
Trajectory(layer, ps, st, solutions, residuals)

Assemble saved segment solutions and residuals into a Trajectory. Remove duplicate samples at continuous handoffs while retaining both sides of initial-condition resets. Saved state arrays, parameters, and Lux state are shared.

Experiments

Observations and experiments belong to Corleone and can be used independently of CorleoneInverse. Prepare the observation grid with experiment_state, predict with layer(experiment, ps, st), and compare predictions with residual.

Corleone.Observation — Type

Measurements y of one observed quantity at the sorted, unique times t. Symbolic bookkeeping

Corleone.ControlSymbolCache — Type
struct ControlSymbolCache{__T_sys, __T_controls, __T_quadratures, __T_bounds, __T_integers}

Wrap a SymbolicIndexingInterface symbolic container with bookkeeping metadata. controls selects parameters; quadratures selects states that integrate running costs. Selections accept symbols or original indices. All symbols retain their original kind, index and ordering. Controls remain parameters.

bounds maps state or parameter symbols to (lower, upper) pairs. integers lists the state and parameter symbols whose optimization values are integral. The parent container and supplied bounds dictionary are retained by reference, just as the parent's defaults are. Index-provider queries delegate through symbolic_container. A differential equation problem can also be supplied in place of sys.

Fields

  • sys: The original symbolic index provider, retained by reference.

  • controls: The subset of parameter symbols designated as controls.

  • quadratures: The subset of state symbols designated as running-cost integrals.

  • bounds: State and parameter symbols mapped to (lower, upper) bounds, retained by reference.

  • integers: State and parameter symbols whose optimization values are integral.

Corleone.InitialCondition — Type
struct InitialCondition{__T_name, __T_lookup, __T_parameter} <: LuxCore.AbstractLuxContainerLayer{(:lookup, :parameter)}

Corleone.get_lower_bound — Function

Return lower optimization bounds with the parameter layout and array shapes of ps. Containers and wrappers recurse using Lux's declared child fields; NamedTuple, Tuple and array collections recurse over their layers. Generic leaves have unbounded parameters (-Inf). Return a Boolean integrality tree with the parameter layout and array shapes of ps, following the same recursion as get_lower_bound. An entry is true when its optimization value must be integral. Generic leaves are continuous (false).

Corleone.get_number_of_shooting_constraints — Function
get_number_of_shooting_constraints(layer, ps, st)

Count scalar state and parameter matching residuals for the cached segment grid in st.timestops, without running the model. Each tunable initial condition contributes one residual at each matching segment start strictly after the global problem start. Assignments at the global start are free initial values. Each inserted interval of a tunable parameter adds one matching residual, counted once regardless of other segment boundaries within that interval. Original parameter switches, fixed assignments, and resets at the final endpoint contribute none.

Corleone.add_parameter_segments! — Function
add_parameter_segments!(layer, ps, st)

Split tunable parameter intervals at interior full-state resets and return updated (ps, st) for the same layer. New interval values duplicate the previously active value. Their right-hand interval indices are recorded in st's per-parameter lookup.inserted vectors, for subsequent parameter matching constraints.

Existing parameter switches remain unconstrained, and fixed parameters are unchanged. Repeated calls do not insert additional entries. The input arrays and layer are retained unchanged; changed parameter arrays and lookup grids are newly allocated, and affected lookup caches are cleared. Segment boundaries are read from the current initial-condition schedules and the stored problem span; the returned state's cached timestops are refreshed. No solve, initialization, or constraint construction occurs.

Corleone.adapt_timegrid! — Function
adapt_timegrid!(layer::ShootingLayer, ps, st, pairs...; interpolation = :constant, extrapolation = :constant)

Move controls to new time grids and return (new_ps, new_st) for the same layer. Each pair is parameter => grid: the parameter as a Symbol, symbolic variable or original index, and the new sorted switching times strictly inside the problem time span (nothing or an empty grid gives one constant value). A grid of n times stores n + 1 values. The inputs and the layer are not modified.

Each new interval takes the old control's value at the interval midpoint:

  • interpolation = :constant uses the value of the old interval containing the midpoint, so refining a grid reproduces the old control exactly.
  • interpolation = :linear interpolates linearly between the old values placed at their interval midpoints. Outside the first and last old midpoints, extrapolation = :constant holds the end value and :linear extends the end slope. Results are rounded for integer parameters and clipped to the bounds of identity-transformed parameters. Other transforms interpolate internal values.

extrapolation has no effect with constant interpolation, since the old control covers the whole time span. Parameters that share a time grid (for example all untimed parameters) are stored together; supply the same grid for every member of such a group. Fixed (Constant) parameters are resampled the same way. Adapted groups lose their parameter matching equalities; if any were inserted by add_parameter_segments!, segments are inserted again on the new grids. st.timestops is refreshed. Rebuild optimization problems afterwards.

Corleone.shooting_constraints — Function
shooting_constraints(trajectory)

Corleone.constraint_jacobian_sparsity — Function
constraint_jacobian_sparsity(prob; vectorize, ps, st)

Return a conservative sparse Boolean constraint Jacobian pattern for a prepared ODE shooting problem. Columns follow pack(vectorize, ps); rows follow optimization_constraints. Parsed Expr constraints (including lowered MTK constraints) use their referenced state/time and parameter/time dependencies. Literal vectors retain separate dependencies per component. Elementwise series expressions such as :(identity(u₁)) or :(u₁ .- 0.5 .* p₂) (see Corleone.elementwise_series_expression) give row k only the dependencies of saved sample k, plus any timed signals. A saved sample depends on the values starting its segment, the active parameters and the controls applied before it; both sides of a saved reset are kept apart. Corleone.elementwise_series_expression — Function
elementwise_series_expression(expr, indices) -> :series, :scalar, or nothing

Classify an expression syntactically for per-sample series sparsity. :series means output element k reads only saved sample k of every referenced series signal (plus scalar timed signals); :scalar means a timed signal or a constant; nothing means neither can be guaranteed.

The rule is deliberately conservative. An expression is elementwise if it is

  • a bare series signal such as u₁ or p₂;
  • identity(x) of an elementwise expression x;
  • a dotted call f.(args...) or dotted operator such as a .* b, .-a or a .<= b, whose arguments are all elementwise or scalar, with at least one series argument.

Scalar arguments are timed signals such as u₁(2.0), numeric literals, interpolated numeric values or arrays, and dotted calls of scalar arguments only. Everything else (for example sum(u₁), cumsum(u₁), undotted calls such as u₁ * 2, indexing, vector literals, global names, and @./.= forms) is not elementwise and keeps the union of all its dependencies in every row. Row sparsity is additionally applied only when the output length equals the number of saved samples.

Corleone.optimization_dependency_rows — Function
optimization_dependency_rows(prob, initial, reconstruct, st; hessian = false)

Return the structural column dependencies of a prepared problem as (; user, matching, matching_hessian, objective), each a vector of BitSets of packed column ids. user has one row per user constraint entry and matching one per shooting equality; with hessian = true, matching_hessian holds the curvature rows of the shooting equalities and objective the objective's coupled column cliques, otherwise both are empty. constraint_jacobian_sparsity and lagrangian_hessian_sparsity build their patterns from these rows.

Sublibraries add methods for problems whose layer is not a shooting layer, building the rows with dependency_column_ids, shooting_dependency_context and trajectory_constraint_dependencies.

Corleone.dependency_column_ids — Function
dependency_column_ids(prob, reconstruct, ncolumns, st)

Return the parameter tree of prob with each leaf replaced by its packed column id, reconstruct(1:ncolumns) normalized for repeated tree access. Throw ArgumentError when the shooting schedule in st no longer matches the one prob was prepared for. Pass the result, or its subtrees, as ids to shooting_dependency_context.

Corleone.shooting_dependency_context — Function
shooting_dependency_context(shooting, ids, st, times, expressions; evaluation = nothing, packed_ids = nothing, hessian = false, saved_samples = false)

Analyze which packed columns the trajectory of shooting depends on, without solving. ids is the shooting parameter tree of column ids, st the prepared shooting state, and times the saved time grid. expressions lists the constraint and objective functions to inspect; parsed expressions refine which samples are resolved and other values are ignored. Pass the wrapping evaluation::EvaluationLayer and the packed packed_ids tree containing ps.evaluation ids to resolve evaluation signals. Set saved_samples = true to resolve states at individual saved samples.

Return (dependencies, resolve). dependencies.matching and dependencies.matching_hessian hold the shooting-equality rows. resolve(signals, sample) returns the BitSet of columns that the (kind, index, time) signals read, where sample selects a saved sample index for series reads, or nothing for their entire history. See expression_signals.

Corleone.trajectory_constraint_dependencies — Function
trajectory_constraint_dependencies(f, n, resolve, columns, nsamples)

Return n dependency rows (BitSets of column ids) for the constraint or objective function f with n outputs on a trajectory with nsamples saved samples. Parsed expressions resolve their signals with resolve from shooting_dependency_context. Opaque callbacks may read any value they can access: every row then holds columns, either a BitSet or a column count ncolumns for 1:ncolumns.

Corleone.expression_signals — Function
expression_signals(f)

Return the (kind, index, time) signals read by a compiled trajectory or observation expression, or nothing for an opaque callback. kind is :states, :parameters, :time, or :evaluation; time === nothing denotes a read of the entire series (or, for observations, of the current sample). Resolve them to columns with the resolve function of shooting_dependency_context.

Corleone.dependency_pattern — Function
dependency_pattern(rows, nrows, ncolumns)

Return the nrows × ncolumns Boolean sparse matrix whose row i has entries at the column ids in rows[i], typically BitSets produced by optimization_dependency_rows or shooting_dependency_context.
