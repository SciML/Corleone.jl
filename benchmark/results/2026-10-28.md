Scope: the root Corleone package, excluding `lib/`. Local Julia 1.12.7 on Linux;
this is not a claim that the complete CI version/platform matrix has passed.
The working tree starts at `0d29c5b`, with the solver-independent precompile
workload and benchmark scripts added for this validation.

## Precompilation

`src/precompile.jl` exercises annotation resolution, symbolic bookkeeping, Lux
setup, fixed/tunable/pass-through initial conditions, parameter switches, and
schedule extraction. It introduces no solver dependency and does not precompile
an ODE solve. `Pkg.precompile(["Corleone"]; strict=true)` succeeded; the package
workload took about 5.04 seconds and its RuntimeGeneratedFunctions extension took
0.82 seconds in that run. These build times are not first-user-call timings.

alternating the empty-workload baseline (`0d29c5b`) and the new workload. Each

## Forward solve versus archived main

`benchmark/forward_comparison.jl` uses the shared benchmark suite's Lotka ODE:
three physical states, `[0, 12]`, 120 zero-control intervals, and tolerances
`abstol=1e-8`, `reltol=1e-6`. Multiple shooting resets all physical states at
`3`, `6`, and `9`. Non-control parameters remain numerically fixed at one.
The archived main uses the old constructors and representation; the rewrite uses
native annotations. Physical-state terminal values agree to `1e-12`. Main's
trajectory additionally contains an appended control entry, which is not included
in that physical-state comparison.

First calls use an inference barrier so specialization takes place inside the
timer. Single shooting runs first in each fresh process; multiple shooting then
reuses common compilation. These times exclude package loading, construction,
and Lux setup. Warm medians use up to 500 samples (`evals=1`, ten-second budget).

| Case | Checkout | First call (s) | Warm median (ms) | Bytes | Allocations |
|---|---|---:|---:|---:|---:|
| Single | Main e98dc06 | 13.0621 | 0.252527 | 847,072 | 17,632 |
| Single | Rewrite | 1.5855 | 0.243217 | 862,872 | 17,495 |
| Multiple | Main e98dc06 | 2.0658 | 0.261382 | 894,616 | 17,927 |
| Multiple | Rewrite | 0.2274 | 0.255927 | 860,568 | 17,428 |

The measured first-call speedups are **8.24×**
for single shooting and **9.09×**
for the incremental multiple-shooting call. Warm runtime differences are small;
these samples do not establish a universal runtime ranking. Single-shooting bytes
increase by about 1.9%; multiple-shooting bytes decrease by about 3.8%.

## Threaded forward solve

`benchmark/shooting_parallel.jl` uses four Julia threads, 120 integration segments,
and 12 independent full-state blocks. The expensive right-hand side adds 256 sine
terms. Serial and threaded trajectories and residuals are checked for agreement
before measurement. Medians use up to 500 samples, one evaluation per sample.

| Workload | Mode | Median (ms) | Bytes | Allocations |
|---|---|---:|---:|---:|
| Cheap RHS | serial | 0.258202 | 632,584 | 12,073 |
| Cheap RHS | threads | 0.105084 | 684,944 | 12,609 |
| Expensive RHS | serial | 6.289957 | 632,584 | 12,073 |
| Expensive RHS | threads | 1.661516 | 684,944 | 12,609 |

Four-thread speedups: **2.46×** (cheap RHS), **3.79×** (expensive RHS). These are model-specific measurements.

## Serial gradient compatibility

`benchmark/shooting_ad.jl` uses eight control values, or 16 values after lifting
three states at two reset times and splitting crossing parameter intervals.
It uses the public `layer(nothing, ps, st)` call. The historical 26 October script
used the direct `(problem, tstops)` call, so its timings are not an exact matched
baseline for these results. The tolerance, loss, and model are described in
`benchmark/README.md`.

Each backend ran in a fresh process with its required dependencies. Successful
prepared gradients were checked at two inputs against central differences, with
preparation reused and input vectors checked for mutation. Maximum discrepancies
were below `3.5e-10`. FiniteDiff is a numerical reference, not an AD backend.

| Configuration | Controls | Joint states/parameters |
|---|---|---|
| ForwardDiff | Pass | Pass |
| ReverseDiff (pass-through) | Pass | Pass |
| Zygote | Pass | Pass |
| Mooncake reverse | Pass | Pass |
| Enzyme forward | Fail | Fail |
| FiniteDiff | Pass | Pass |
| ReverseDiff (default) | Fail | Fail |

ReverseDiff pass-through, Mooncake, and Enzyme use `FullSpecialize` and
`SensitivityADPassThrough()`. ForwardDiff, Zygote, and FiniteDiff use the default
solver sensitivity setting; Zygote has SciMLSensitivity loaded. Mooncake passes
without caller-side promotion of the problem initial state. These are serial
checks, not validation of compiled ReverseDiff tapes or parallel Mooncake/Enzyme.

Enzyme forward still fails with LuxCore's rejection of non-Const layer annotations,
despite `function_annotation=Enzyme.Const` and runtime activity being enabled.
Default ReverseDiff still returns a `ReverseDiff.TrackedArray` from the solve;
`internal_solve` requires an `AbstractSciMLSolution` for the subsequent segment.
The array also lacks saved-time and other solution metadata required by trajectory
assembly. Neither failure is hidden by the passing maintained test groups.
