# Generated experiment traversal — 10 November 2026

Preparation and batch execution now generate literal property accesses from the
NamedTuple fields in Lux state. The generators inspect types and field names only;
they do not read numeric values, run initializers, or construct models during
generation. Declaration order is retained when state fields are reordered, and
missing/mismatched experiment fields raise ArgumentError.

Mixed trajectories retain the public Vector API, with an element type that is a
finite union of the concrete result types. Matching layouts use a single concrete
element type. The checked paths no longer widen to Any or abstract Trajectory.

## Inference and correctness

All twelve return-type comparisons (preparation, individual solve, and batch;
native/ComponentArray; matching/mixed layouts) infer their exact runtime types.
Regression tests additionally use `@inferred` with mixed grids, constants,
transforms, and one/two/three experiments, check declaration order after state
reordering, and check schema errors.

Validation passes: 81 inference/schema checks, 81 existing experiment checks,
39 inverse checks, eight analytical AD checks through generated preparation,
201 focused legacy regression checks, and 44 root/inverse QA checks with one
pre-existing expected-broken check. ForwardDiff, ReverseDiff, and Zygote agree
with analytical gradients for inactive shooting nodes and transformed variables.
The executable fitting example, Runic checks, and draft documentation build pass.

## Method

The workload is `benchmark/experiment_layers.jl`, with the same models and resolved
dependencies as the preceding non-generated implementation. Before results are
recorded in `experiments-benchmark-{1,2}.csv`; generated results in
`generated-benchmark-{1,2}.csv`, under `/tmp/corleone-experiment-unknowns`.
Both implementations are uncommitted development snapshots.

Julia 1.12.7, AMD Ryzen 7 8700F, one Julia and BLAS thread, CPU 6. Two fresh
benchmark processes run sequentially; validation jobs run on other CPUs.
BenchmarkTools uses 500 samples with a one-second sampling budget. Loading,
compilation, construction, and warm-up are excluded. Ranges are process medians,
not confidence intervals. The larger workload has 24 initial variables and
controls per experiment, with 19 interior reset/switching times. Numeric outputs
are checked against direct shooting calls before measurement.

ComponentArray tuple preparation improves by approximately 15× in the small
workload and 37–40× in the larger workload. Its previous 37 view allocations are
eliminated. Full ComponentArray batch allocation counts now match native batch
execution. The remaining batch cost includes the requested trajectory vector,
returned state, and retained local annotation metadata.

These are warmed inference/forward checks, not guarantees about arbitrary custom
parameter containers, AD backends beyond those tested, compilation time, or very
large heterogeneous batches. A finite union specifies possible vector element
types; it does not turn heterogeneous values into one identical concrete type.

## YAGNI follow-up

A subsequent cleanup removes redundant Lux initialization methods, repeated base
collection scans, duplicate grouping/timestep code, and the extra trajectory-vector
generator. Ordinary tuple-type specialization preserves the same concrete/finite-
union vector inference. The generators for named state fields are retained in preparation and batch
execution to preserve the inference guarantees checked above.

Global transform bounds are normalized once, then local overrides update copied
metadata. This preserves explicit transforms that replace model bounds, without
reconstructing parameter collections for each trajectory cache.

Follow-up measurements in `yagni-benchmark{,-2}.csv` retain zero allocations for
native/ComponentArray tuple preparation and unchanged batch allocation counts.
Using generic Lux setup instead of custom wrappers costs approximately 2 µs more
for the small two-experiment case and 8–10 µs for the 24-variable case, paid once
at setup. Setup allocations increase by 35 and 28 respectively. This trades a
small one-time cost for fewer custom initialization methods; forward allocations
remain unchanged. The historical draft reports were archived outside the checkout.
